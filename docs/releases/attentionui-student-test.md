## 修改范围

本轮按用户“项目里的所有地方”要求，统一修改当前品牌及相关标识：

- 根项目、Desktop、Extension、Shared 和 PDF 实验包的 npm 名称与 workspace 引用。
- 桌面窗口、托盘、安装名称、快捷方式、卸载显示、程序文件名与图标文字信息。
- Chrome 插件 Manifest、弹窗、设置页、内容工具、DOM/CSS 标识和错误提示。
- 健康服务标识、共享类型、错误码、桌面 Preload/IPC 和插件消息命名。双端必须使用同一套新版本产物。

- 本地介绍页的 AttentionUI 标题、页面文件名、路由和测试引用；这是原有未提交介绍页工作，仅同步文字与命名，未发布网站。

所有文件及用途见 `attentionui-renaming-files.json`。其他原有未提交改动、讲义 PDF 和个人配置未纳入本轮提交或分发包。

历史交付记录、已生成的旧安装包与归档保持原样。实际 GitHub 仓库地址和本地工作目录保留真实路径。旧名称还用于识别既有配置文件，避免迁移失效；这些引用不作为当前应用名称。

## 配置迁移

启动时尝试从旧版本的应用配置目录读取设置、配对和习惯文件，通过共享 Schema 校验后复制到新的配置目录及文件名。只复制已知文件，不改写原文件，不覆盖已有新配置；迁移失败记录不含文件内容的提示，程序仍可启动。

回归测试覆盖三类数据保留、原文件保持不变、新设置优先、重复启动不覆盖、非法结构跳过及损坏 JSON 不阻断。显式 `--user-data-dir` 的独立测试启动不读取其他应用配置。
