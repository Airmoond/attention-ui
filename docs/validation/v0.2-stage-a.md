## 手动复验

1. 在 `tools/pdf-spike` 运行 `npm ci`、`python generate-fixtures.py`、`npm run dev`。
2. 打开 http://127.0.0.1:4178，选择 `fixtures/sample-03.pdf`。
3. 滚动到第 2 页，点击两次“+”放大到 150%，拖选正文或页码锚点；点击“记录此片段”。
4. 切到第 3 页，再点击“返回来源页”，确认回到第 2 页，片段与原文对应。
5. 点击“适合宽度”，跨页拖选，确认片段标注起止页码；在正文外的空白处滚动，确认文档随之连续移动。
6. 点击“网页全屏”，确认侧栏与工具栏保留；按 Esc 退出。
7. 关闭文档，确认片段消失；依次打开异常样本，核对提示。
8. 若测试真实学生资料，仅在本机打开；此实验没有上传或 AI 入口。

## 阅读交互反馈修复（2026-09-23）

根据试用反馈，将单页嵌套滚动框改为由浏览器窗口统一滚动的连续页面；鼠标位于正文外的空白处也能滚动文档。增加加减缩放、“适合宽度”和网页全屏按钮，展开后保留片段侧栏，Esc 可退出。页码输入仅用于快捷定位，不再要求按下一页。跨页拖选可记录起止页码，返回片段起始页。

页面按需绘制，回收远处画布，保留已访问页面的文字层以支持跨页选择；已完成画布最多保留 5 张，并限制其总像素预算。该策略并非整个解析器内存的硬性上限。

本次独立验证页类型检查与构建通过，浏览器测试 **25/25 通过**。在原用例基础上新增：正文外滚轮连续阅读、网页全屏及退出、真实鼠标跨页拖选、快速缩放与文件替换、12 页文档跳转及画布回收后重绘。新增 `fixtures/continuous.pdf` 由原创样本重复生成，未扩大真实学生资料的覆盖范围。

截图位于 `tools/pdf-spike/test-results/continuous-fullscreen.png` 和 `cross-page-selection.png`，仅作本机验证，不提交。自动测试使用 4179 端口，手动阅读页仍使用 4178 端口。

本次修改范围为实验目录的 `index.html`、`src/main.ts`、`src/style.css`、`tests/pdf.spec.ts`、`playwright.config.ts`、`generate-fixtures.py`、`README.md` 及本报告，共 8 个文件。正式应用源码未改动；本次没有重复运行原项目的 141 项测试。真实复杂 PDF、长文档解析内存峰值和正式插件集成仍按原计划继续验证。


## 段落拖选误扩展修复（2026-09-23）

用户提供的本机讲义与原创样本均复现：从第一段拖到末行右侧空白，浏览器原生选区跳到后面的内容。原实现只调用底层 `TextLayer`，缺少官方阅读器的选区边界管理。新增的四项回归测试在修改前均失败，真实讲义首段选区混入公式与下一段。

改用当前已安装 PDF.js 的 `TextLayerBuilder`，接入选区边界、拖选状态及复制处理；保留文字归一化，缩放/关闭时取消文字层以释放监听器。在同一行左右空白处松手时，将选区端点落到最近的文字边缘，避免漏掉首尾字符。没有新增依赖。

本次修改 4 个文件：`tools/pdf-spike/src/main.ts`（文字层接入与空白处端点修正）、`tests/pdf.spec.ts`（正反向段落、缩放、单词与可选本机讲义用例）、`README.md`（操作及本机讲义复验方法）、本报告（根因及验证证据）。

在实验目录执行 `npm run build`（含类型检查）、设置 `FOCUSUI_TEST_PDF` 后执行 `npm test`。真实讲义截图保存于 `tools/pdf-spike/test-results/local-lecture-selection.png`，文件及截图只在本机保留，不加入提交。默认测试不依赖该讲义文件。

手动验收：刷新阅读页并重新打开讲义，拖选第一段至“hypothesis function is defined by”右侧空白，确认只有首段高亮；反向拖选和只选一个词应保持精确，再检查缩放及跨页拖选。数学字体中个别符号的文字提取仍与原文不完全一致，本次修复针对选区范围，不代表公式语义提取已经通过验收。

最终结果：类型检查与构建通过；浏览器用例 **30/30 通过**，包含用户讲义、100%/150% 段落边界、反向拖选、只选一个词，以及原有的跨页选择、缩放与换文件回归。未提供本机讲义时为 29 项运行、1 项跳过。构建保留单个脚本包超过 500 kB 的体积提示，不影响本次功能验收；正式应用源码及安装包未变动。当前拖选范围修复满足已执行的验收用例，等待用户复验手感。
