## B1：设置与选区边界

网站策略单独保存于 `sitePoliciesV1`，不覆盖旧版桌面地址、配对令牌和全局开关。升级后所有站点默认未启用，启用后仍默认手动，自动工具条与自动 AI 推荐分别开启。损坏策略按未启用处理。临时暂停使用浏览器会话存储，按标签页隔离。

仅允许中英文维基百科、百度百科及既有本机 Demo。发送上下文将以浏览器提供的真实来源地址为准，去掉查询参数和片段，省略网页标题和邻近标题；存在选区时只保留选区正文。手动选区跨过输入框、表单或可编辑区域时整体拒绝。

涉及文件：共享 `extension.ts` 定义版本化网站策略；`site-access.ts` 实现默认值、存储、访问判断及上下文最小化；`site-access.test.ts` 验证迁移与边界；`manual-selection.ts` 提供安全的手动选区入口；本文记录范围与验收。B1 为基础子步骤，随后 B2 接入实际界面与运行流程。

B1 验证：根目录 `npm run typecheck` 与 `npm run build` 通过；共享 10、桌面 55、插件 89 项测试通过，共 154 项（新增网站边界 13 项）。保留既有 WXT/Vite 弃用提示。网页交互和权限授权的实际接入在 B2 完成后验证。

## B2：弹窗与实际网页流程

已接入当前网站启用/禁用、仅当前标签页暂停/恢复、选区手动工具按钮与 Alt+Shift+F。两个自动开关独立：默认不会自动显示工具条，也不会自动请求 AI 推荐。开启自动工具条但关闭自动 AI 时，仅本地推断并显示工具。弹窗说明开启自动 AI 会额外发送片段及可能产生费用。

百科与 8080 Demo 地址改为可选网站权限，在用户点击启用时申请；只注册用户启用且拥有权限的网站内容脚本，已有页面按需注入。权限撤销、禁用或暂停时清理页面界面；后台在执行请求前再次判断访问状态。配对和全局设置仅插件自有页面可访问，网页内容脚本不能读取令牌或修改网站设置。组件卸载会使旧响应失效。

本子步骤修改 8 个文件：`wxt.config.ts`（可选权限）、`entrypoints/background.ts`（注册、控制与请求授权）、`entrypoints/content.tsx`（按需启动与手动入口）、`entrypoints/popup/App.tsx`（控制界面）、`src/communication/messages.ts`（校验消息）、`src/ui/FocusUIRoot.tsx`（自动 AI 分离与卸载清理）、`src/control/runtime.test.ts`（后台集成边界）、本文。

验证：插件类型检查与构建通过；插件 99 项单元/集成测试通过（基础 76 + B1 13 + B2 10）。使用独立 Chrome for Testing 153.0.8010.12 加载真实构建插件完成 10 项浏览器操作检查：默认关闭、弹窗启用并注入、手动默认不触发 UI/AI、快捷键唤起、手动 AI 上下文最小化、暂停清理、跨可编辑区域拒绝、纯本地自动工具条、AI 推荐独立开启、禁用后刷新保持关闭。AI 服务使用测试替身，没有读取真实密钥或产生供应商请求；此结果不等于百科真实页面适配已验收。

## B3：边界回归、交付与验收状态

后台新增权限撤销回归：移除动态脚本注册，并通知已加载的页面清理。此项用模拟 Chrome 事件的集成测试验证；原生授权弹窗未在无界面浏览器中完成交互验收。没有把模拟授权当作真实用户确认。

### 用户体验步骤

1. 在 Chrome 扩展管理页加载 `E:\Airmond\focus-ui\apps\extension\.output\chrome-mv3`。如果已加载的就是该目录，点击重新加载；如果之前加载的是发布包目录，需要改为这个新构建目录。刷新待测试网页。
2. 打开中英文维基百科或百度百科，点击浏览器工具栏里的 FocusUI 图标。点击“启用此网站”，确认 Chrome 的网站授权提示。升级后第一次需要启用网站，旧配对保留。
3. 先保持两个自动开关关闭。在正文选中文字，按 Alt+Shift+F，或从插件弹窗点击“对选中文字使用工具”。确认工具条出现；点击总结/解释/提问才发送片段。真实 AI 使用现有桌面配置并可能产生费用，本轮未代替用户执行。
4. 开启“鼠标停留时自动显示工具条”，保持自动 AI 推荐关闭，观察本地工具条；仅在希望额外自动请求时开启 AI 推荐。
5. 暂停当前标签页，应立即清理界面，其他标签页仍可用。恢复后可继续操作；禁用网站后刷新仍应关闭。
6. 在 Chrome 中撤销该网站授权，确认界面清理，刷新后不再自动注入。再次使用时重新授权。首次授权/拒绝、原生权限提示、普通 Chrome 重启及真实百科结构仍需人工复验。

## 人工验收修复：悬停不能覆盖正在使用的窗口

用户反馈：点击解释后，等待 AI 时移到另一段，窗口消失。旧构建已通过新增浏览器回归复现：移到另一段停留后，加载窗口不再存在。根因是自动关注事件替换会话，同时使旧 AI 请求版本失效。

现在等待 AI、显示结果/错误、输入问题和专注阅读期间，自动悬停不接管当前交互，也不请求新片段的自动 AI 推荐。显式选文快捷键仍可切换内容；关闭、Esc、返回及原有点击外部关闭行为保留。被忽略的悬停不会在关闭后补弹旧工具条。关闭/暂停后的旧响应仍不能恢复界面。

本修复修改 4 个文件：`entrypoints/content.tsx` 区分自动悬停和手动选文；`src/ui/FocusUIRoot.tsx` 同步维护当前交互状态，仅接受允许的会话切换，并保留请求版本保护；`scripts/test-site-controls.mjs` 新增交互稳定性回归并等待弹窗实际关闭，避免测试导航竞态；本文记录验证与人工步骤。无新增依赖。

验证结果：

- `npm run typecheck`：通过。
- `npm run build -w apps/extension`：通过，保留既有 WXT/Vite 弃用提示。
- `npm run test -w apps/extension`：109/109 通过。
- `node scripts/test-site-controls.mjs`：Chrome for Testing 153.0.8010.12，20/20 通过。新增等待解释保持原上下文、结果不被覆盖、关闭恢复自动工具条、问题草稿保持且无额外 AI 推荐、手动选文可切换当前交互共 5 项。测试使用延迟的本机响应替身，不调用真实 AI。
- 根目录 `npm test`：共享 10/10；桌面 51/55，4 项服务测试因用户正在运行的 `E:\Airmond\FocusUI\App\FocusUI.exe` 占用 127.0.0.1:17321 而失败，随后流程停止。没有停止用户桌面程序，没有将此轮全项目测试报告为全部通过；插件测试另行执行并通过。
