# 混合正文与公式：本机识别实验

日期：2026-09-23。分支：`codex/v0.2-real-world`。用户授权尝试“继续拖选整段，内部补全公式”的方向，不使用远程识图 API。

## 结论

交互与数据通路已跑通：拖选文字 → 数学区域定位 → 普通正文与公式原图按原顺序组合 → 点击本机识别 → 对照原图校正 → 复制带 LaTeX 的文本。支持多页片段并保留来源页码。无需切换成框选模式。

**公式识别准确率尚未通过验收。** 用户讲义第 6 页固定片段检测到 5 处公式；本次人工核对只有概率密度分式完整符合原文，其余 4 处短符号或括号错误。39 项自动用例通过说明工程流程和已覆盖的回归成立，不代表公式内容准确率达标。

正式 Desktop/Extension 未集成或重新打包。本机实验不访问 DeepSeek，不读取 API Key，不发送讲义到外部服务。当前仅开发服务可执行识别；静态构建产物本身不包含 Python 服务。

## 本轮实现

- 复用 PDF.js 文字层与原生拖选。通过实际字体名及空间邻近关系识别数学片段，使用完整公式组替换被选中的乱码片段。
- 普通文字直接提取；公式从 PDF 原始绘制内容以固定 3 倍比例裁剪，不受屏幕缩放和蓝色选区覆盖影响。预览中的公式是原图，不是识别结果的重新排版。
- 保持正文、行内公式、独立公式及跨页来源顺序；选区触及公式时保留该公式组整体。公式分组属于启发式实验，并非通用论文版面分析器。
- 点击“本机识别公式”才运行模型。每批最多 12 处、请求最多 4 MB、单图最多 400 万像素、服务执行超时 90 秒。识别失败保留原图并允许重试，不伪造公式。
- 结果标记待核对；展开每个公式可以修改 LaTeX。复制时按原位置插入 `\(...\)`，供后续文本模型使用；当前没有自动发送功能。
- 清空选区、缩放或换文件取消旧任务；过期响应不能覆盖新选区。保存片段保留原图，关闭文档清除保存内容。
- 本机适配器随 Vite 绑定在 `127.0.0.1`，限制来源、使用随机会话令牌、校验请求与结果、限制并发为 1。识别进程只接收公式图片；不接收文件路径或整份 PDF。服务不记录公式图片、原文及识别输出。
- 模型文件必须提前准备；推理进程禁用网络连接，并显式引用本地模型，缺少模型时返回失败而非临时联网下载。

## 运行与复现

需要项目根目录完成 `npm ci`（实验复用项目已有 Zod）；Python 3.12。当前机器为 Windows、32 GB 内存；本轮使用 CPU 推理，不要求配置 CUDA。

在 `tools/pdf-spike` 执行：

```powershell
npm ci
python -m venv .formula-runtime
.formula-runtime/Scripts/python.exe -m pip install -r formula-requirements.txt
# 首次联网准备官方模型；此时不读取任何用户文档。
.formula-runtime/Scripts/python.exe -c "from rapid_latex_ocr import LaTeXOCR; LaTeXOCR(); print('Ready')"
python generate-fixtures.py
npm run dev
```

打开 http://127.0.0.1:4178，选择讲义。在第 6 页拖选从“We assume”到下方公式后的部分正文。右侧出现“文字与公式”，原文、公式图像和后续文字顺序应保持一致；点击“本机识别公式”，展开结果逐项核对。只拖选普通文字时沿用原有行为。单击空白处取消当前片段，已记录的内容保留。

构建与自动验证：

```powershell
npm run build
$env:ATTENTIONUI_TEST_PDF = '本机路径\Lecture2-LinearReg-Notes.pdf'
$env:ATTENTIONUI_TEST_OCR = '1'
npm test
Remove-Item Env:ATTENTIONUI_TEST_PDF, Env:ATTENTIONUI_TEST_OCR
```

本轮类型检查与构建通过，**39/39 浏览器用例通过**（约 52 秒）。包含原有 33 项、新增混合顺序与原图、跨页来源、保存清理、模拟过期响应、接口边界、识别失败，以及真实本机 OCR。未提供本机讲义及 OCR 标记时，37 项运行、2 项跳过。需要模型的只有真实 OCR 验证；它没有用模拟结果替代真实识别。

## 实测结果及限制

| 第 6 页片段 | 本轮结果 |
|---|---|
| 行内噪声符号 ε | 被误识为花体 E，未通过 |
| 行内正态分布 | 括号有错误，未通过 |
| 带上标的噪声符号 | 主符号错误，未通过 |
| 完整概率密度分式 | 与原图一致，通过；一次单独 CPU 推理约 1.315 秒 |
| 行内变量 y | 被误识为其他花体字符，未通过 |

该统计仅针对一份真实讲义的一个固定片段，不能推及其他 PDF。原图保真预览可以弥补阅读时的信息损失，但不能代替正确的可复制公式。

当前检测优先覆盖可获取字体名的 Computer Modern、Symbol 和含 Math 标识的数学字体。未解决任意字体的公式检测、扫描件、复杂多栏阅读顺序、矩阵边界、公式跨行/跨页分组及所有旋转排版。不能将“未检测到公式”解释为“该段没有公式”。

下一步应先建立行内符号、分式、上下标、求和、矩阵的独立正确率基线，比较更适合混合正文的本地识别引擎或字体解码方案。达到准确率要求后再迁入 Desktop，明确模型分发许可、模型准备入口及安装体积。暂不把本轮候选文本接入自动问答。

## 第二轮：缩放改进尝试后暂停（2026-09-23）

用户要求再尝试一轮，效果仍不好就停下，交由用户体验后决定是否继续。本轮已停止优化，应用仍保留上一轮的原图预览与识别实现；没有把未经验证的缩放策略替换到阅读器。

检查五张原始裁剪图后，对相同输入比较原始模型与四种固定墨迹高度（16、24、32、48 像素），合计 25 次离线推理。实验先按墨迹边界裁剪、等比例缩放，再补齐模型要求的尺寸，绕过其自动尺寸预测；模型权重保持不变。全部在本机执行，不新增依赖或下载模型。

| 样本 | 缩放尝试的观察 | 是否解决 |
|---|---|---|
| ε | 仍返回花体 E、C 或其他无关内容 | 否 |
| 正态分布 | 24 像素高度得到 `\mathcal{N}(0,\sigma^{2}).`，括号恢复正常 | 局部改善 |
| 带上标的 ε | 仍把主符号识为花体 E | 否 |
| 完整概率密度分式 | 原始处理正确；48 像素保持等价公式，较小高度破坏分式或生成多余内容 | 原始处理更稳妥 |
| y | 16 像素返回 `\boldsymbol{y}`，错误引入粗体；其他尺寸仍识错 | 否 |

即使只对短公式采用本次较好的 24 像素策略、完整分式沿用原始处理，这个已参与调参的片段也只由 1/5 提升至 2/5。它不是独立测试集准确率，更没有证明其他论文会改善，因此未采用该策略。不能通过把已知错误结果直接替换为预期符号来掩盖问题。
